## Goal
A reader can use wikimemory in Finnish, Swedish or English: every visible UI string comes from one
string table per language, the language is picked from the browser and remembered, and
LLM-generated text (summaries, answers) is produced in the reader's language while every fact
keeps its original-language source sentence and a link back to the exact Wikipedia revision. When
the reader's language differs from the article's, the sibling article in the reader's language is
offered. Language only: no accessibility work in this spec.

## Assumptions
- Reader language = UI language = `ui`, one of `fi`, `sv`, `en`. "Article language" = `article.lang`.
- The sibling article is already in the API: `GET /api/article/{lang}/{page_id}` returns
  `other_languages: [[lang, title, url], ...]` (same wikidata_id, via `rag_common.other_languages`).
  No backend change is needed for the offer; the panel's existing language-version buttons already
  open a sibling with `onSearchSubmit(title, lang, { openDirectly: true })`. Reuse that handler.
- Switching language reloads the page (`location.reload()` after saving the choice). All strings
  are applied once at startup; no live re-render plumbing through `src/ui.js`. Open state
  (article, Summarize, Ask) is lost on switch: accepted (see open questions).
- Language names inside sentences come from `Intl.DisplayNames(locale, { type: "language" })`
  (e.g. "suomi", "Swedish"); phrases that need grammar (Finnish elative "suomesta") are whole
  strings in the table.
- Intl locales: `fi -> "fi-FI"`, `sv -> "sv-FI"`, `en -> "en-GB"`. Years are never passed through
  the number formatter (fi would print "2 003").
- Summary section `heading`, ghost section text, article titles, categories and all Wikipedia text
  stay in the original language (they are verbatim Wikipedia text).
- Legacy cache rows (built before this spec) are the "no `ui`" default and stay valid unchanged; they
  have no `out_lang` field. Clients treat a missing `out_lang` as: summary -> `article.lang`;
  ask -> `null` ("the language of the question").
- Translations of UI strings are written by Hydrogen; load-bearing phrases are fixed below.

## API contract changes (additive; default behaviour unchanged)

### `GET /api/summary/{lang}/{page_id}?ui=<fi|sv|en>`
- `ui` optional. Absent, empty, or equal to `lang` -> exactly today's behaviour and today's cache
  row. Any other value not in fi/sv/en -> HTTP 422.
- NEW field `out_lang`: language of `tldr`, `facts[].label/value`, `sections[].one_line/summary`,
  `sections[].facts[].label/value`. Every fact `source` stays verbatim in the article's language
  (grounding check unchanged: whitespace-normalized substring of the input text).
- Cache: `summary_cache` gains column `ui VARCHAR(3) NOT NULL DEFAULT ''`; PK becomes
  `(lang, page_id, rev_id, ui)`; `''` = article-language default (all existing rows).
- Hit for `(lang, page_id, rev_id, ui)` -> cached JSON (`out_lang` = `ui`, `mode: "llm"`).
- Miss with `ui` set -> answer immediately with the default (`ui=''`) cached row if it exists,
  else today's extractive response; either way the text is in the article's language and
  `out_lang` = `lang` (the UI shows the "not yet translated" note). Schedule ONE background build
  for the `ui` key (in-flight set key becomes `(lang, page_id, rev_id, ui)`). Never await the LLM.
- Example (trimmed):
  ```json
  {"article": {"lang": "fi", "page_id": 1256, "title": "Talvisota", "...": "..."},
   "mode": "llm", "rev_id": 23200000, "out_lang": "sv",
   "tldr": "Vinterkriget var ...",
   "facts": [{"label": "Fredsavtal", "value": "13 mars 1940",
              "source": "<verbatim Finnish sentence from the article>"}],
   "sections": [{"no": 1, "heading": "Tausta", "one_line": "<Swedish>", "summary": "<Swedish>",
                 "facts": [{"label": "...", "value": "...", "source": "<verbatim Finnish>"}],
                 "text": "## Tausta\n\n<Finnish Markdown, verbatim>", "history": {"...": "..."}}],
   "ghost_sections": [{"heading": "<Finnish>", "text": "<Finnish, verbatim>", "oldid": 9876543, "...": "..."}]}
  ```
- Fact link in the UI: `https://<article.lang>.wikipedia.org/w/index.php?oldid=<rev_id>` (summary
  facts have no `url` field; build it from the response's `rev_id`).

### `GET /api/ask?q=...&ui=<fi|sv|en>`
- `ui` optional. Absent or empty -> exactly today's behaviour and today's cache row (answer in the
  question's language). Invalid value -> HTTP 422.
- With `ui`: `answer`, `facts[].text`, `milestones[].answer`, `milestones[].facts[].text` are in the
  `ui` language; every `source_sentence` stays verbatim in its source's language (grounding check
  unchanged); `facts[].url` and `milestones[].url` keep the `?oldid=` link. NEW field
  `out_lang` = `ui` (`null` on default builds).
- Fixed backend strings per `ui` (default stays English, as today):
  - no-answer milestone text: en `The article did not answer this yet.` /
    fi `Artikkeli ei vielä vastannut tähän.` / sv `Artikeln besvarade inte detta ännu.`
  - pending prefix: en `Preparing an answer… Closest passage:` / fi `Vastausta valmistellaan…
    Lähin kohta:` / sv `Svaret förbereds… Närmaste stycke:` (the quoted passage stays original).
- Cache key: `q_hash` = today's `question_hash(q)` when `ui` is absent; with `ui` it is
  sha256 of `normalize_question(q) + "\x1fui=" + ui`. `answer_cache` gains column
  `ui VARCHAR(3) NOT NULL DEFAULT ''` (stored for inspection; PK unchanged).
- Miss with `ui` set -> if the default row for `q` exists, return it (its `out_lang` is absent/null);
  else today's pending response with the localized prefix and `out_lang: null`. Schedule ONE
  background build for the `ui` key (in-flight key = the `ui` q_hash).

### Mock layer
- `src/api.js`: `getSummary(lang, pageId, ui)` and `ask(q, ui)`; append `ui` to the query string
  only when given. All other call signatures unchanged.
- `mockGetSummary(lang, pageId, ui)`: `out_lang` = `ui || lang`; when `ui` differs from `lang`,
  prefix `tldr` and each `one_line` with `[mock] (<ui>) ` (text keeps "[mock]"; `source` unchanged).
- `mockAsk(q, ui)`: `out_lang` = `ui || null`; when `ui` is set, prefix `answer` with
  `[mock] (<ui>) `. Mock text stays marked "[mock]".

## Acceptance criteria

UI language
- [ ] `src/i18n.js` (new) holds `STRINGS = { fi: {...}, sv: {...}, en: {...} }` with identical key
      sets, and exports `lang`, `t(key, vars)` (`{name}` interpolation; plural keys
      `{ one, other }` chosen with `Intl.PluralRules`), `fmtNumber(n)`, `fmtDate(iso)`
      (`Intl.DateTimeFormat`, `dateStyle: "medium"`, `timeZone: "UTC"`), `langName(code)`
      (`Intl.DisplayNames`), `setLang(code)` (save + reload), `applyStatic(root)`.
- [ ] Startup language: saved choice in `localStorage["wikimemory.lang"]` if valid, else
      `navigator.language` starting with `fi` -> fi, `sv` -> sv, else en. Every `localStorage`
      read/write is in `try/catch` (blocked storage = detect again, no error).
- [ ] At startup `document.documentElement.lang` and `document.title` are set to the chosen language.
- [ ] Every visible UI string in `index.html`, `src/ui.js`, `src/main.js`, `src/timeslider.js` and
      `src/scene.js` (visible labels such as "Talvitie winter road", "Unlocated articles",
      "Section removed in {year}") comes from the table: `index.html` static text uses
      `data-i18n="key"` (textContent) and `data-i18n-placeholder` / `data-i18n-title`, applied by
      `applyStatic(document)`; JS strings use `t()`. Includes buttons, tabs, lens names, legend,
      demo chips, placeholders, empty/error messages, "This answer changed N times" (plural),
      tooltips (`title`). Wikipedia/mock content and `aria-label` values are NOT translated.
- [ ] All `toLocaleString("en-US")` calls and hand-formatted counts/dates use `fmtNumber` /
      `fmtDate`. Year numbers are printed raw.
- [ ] A language switcher (placement and look from `docs/design/013-i18n.md`) offers Suomi /
      Svenska / English (endonyms, never translated), marks the current one, and on change calls
      `setLang`. After reload the choice holds.
- [ ] The Ask demo chip is localized per UI language and sends its own question with `ui`:
      en `How did the Winter War end?`, fi `Miten talvisota päättyi?`, sv `Hur slutade vinterkriget?`.
- [ ] `src/i18n.test.js` (node:test, no browser): the three tables have identical keys and no empty
      values; detection maps `fi-FI`->fi, `sv-SE`->sv, `de-DE`->en; a throwing `localStorage`
      stub does not throw; plural selection for 1 and 5 in each language.
      `package.json` `test` script runs both test files.

Content language
- [ ] Article panel: when `article.lang !== ui` and `article.other_languages` has an entry with
      `lang === ui`, show the sibling offer (fi `Myös suomeksi: {title}`, sv
      `Finns även på svenska: {title}`, en `Also in English: {title}`) whose action is the same
      handler as the existing language-version button for that language. No offer otherwise.
- [ ] `main.js` passes the current `ui` to every `getSummary` and `ask` call.
- [ ] Summarize: when `mode === "llm"` and `out_lang === ui !== article.lang`, the overview card and
      each section card show the label (fi `Konekäännös suomesta|ruotsista|englannista`,
      sv `Maskinöversatt från finska|svenska|engelska`, en `Machine-translated from
      Finnish|Swedish|English`, picked by `article.lang`); each fact shows its translated
      `label`/`value` plus the original `source` sentence verbatim in an element with
      `lang="<article.lang>"` and the `?oldid=<rev_id>` link.
- [ ] Summarize: when `(out_lang ?? article.lang) !== ui`, show one note: fi `Ei vielä saatavilla

## Out of scope
- Accessibility of any kind: ARIA attributes or translated `aria-label`s, keyboard navigation,
  focus handling, screen-reader text, contrast. (Explicitly excluded by the user.)
- Translating Wikipedia text, titles, section headings, categories, ghost section text, thread /
  road / topic-road content, backend error `detail` strings.
- Languages other than fi/sv/en; a `?lang=` URL parameter; live re-render without reload.
- Pre-warming beyond the 3 demo articles and the 3 hero questions.

## Failure semantics
